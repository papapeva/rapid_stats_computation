# Правила для агентов

Этот файл читает любой агент, который правит репозиторий.

## Ветки

- Не коммитить и не пушить в `master`.
- Каждую задачу вести в новой ветке от актуального `master`.
- Имя ветки строго `<номер задачи>/<краткое название>`: код задачи, затем короткое имя латиницей через `_`. Пример: `QUI-1/structure_was_built`.
- Заголовок pull request строго `<номер задачи> | <название>`. Пример: `QUI-1 | example_title`. CI проверяет этот формат.
- Не переписывать историю `master` и не делать force push.

## Код

- Язык C++17. Весь код алгоритма в `order_statistic.hpp`, тесты в `order_statistic_test.cpp`. Новые каталоги не заводить без необходимости.
- Ранг `k` нулевой. Функция не меняет входную выборку.
- Новый алгоритм — новое значение `Algorithm` и ветка в `order_statistic`. Существующие тесты должны проходить и для него: они идут по `kAlgorithms`.
- Не добавлять зависимости, бенчмарки и примеры, пока это не нужно для текущей задачи.

## Проверка

После правки C++ собери проект и прогони тесты:

```text
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Перед коммитом прогони `cmake --build build --target format-check`. Стиль задаёт `.clang-format`, статический анализ — `.clang-tidy`.
