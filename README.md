# Быстрое вычисление порядковых статистик

Учебный проект на C++17: поиск порядковых статистик.

Порядковая статистика ранга `k` — элемент, который стоял бы на позиции `k`, если упорядочить выборку. Ранг нулевой: `k = 0` — минимум, `k = n - 1` — максимум.

Код алгоритмов — каталог `algo/`. Базовый класс — `algo/order_statistic_algorithm.hpp`. Любой алгоритм наследуется от `rapid_stats::OrderStatisticAlgorithm` и переопределяет `sort`. Сборка — `CMakeLists.txt`.

```text
algo/order_statistic_algorithm.hpp  абстрактный класс
check_function_comments.py          комментарий в теле функции
CMakeLists.txt                      сборка
AGENTS.md                           правила для агентов
README.md                           эта инструкция
.clang-format                       стиль кода
.clang-tidy                         статический анализ
.github/workflows/ci.yml            проверка pull request на GitHub
```

## Клонирование

```text
git clone git@github.com:papapeva/rapid_stats_computation.git
cd rapid_stats_computation
```

## Ветки

В `master` напрямую не пушат: изменение попадает туда только через pull request и ревью.

Имя ветки строго такое: `<номер задачи>/<краткое название>`. Номер задачи — код из трекера, название короткое, латиницей, слова через `_`. Пример: `QUI-1/structure_was_built`.

```text
git checkout master
git pull
git checkout -b QUI-1/structure_was_built
```

Дальше коммиты делаются в этой ветке. Когда работа готова:

```text
git push -u origin QUI-1/structure_was_built
```

На GitHub открой pull request в `master`. Заголовок pull request строго начинается с номера задачи: `QUI-1 | example_title`. CI отклонит другой формат. После замечаний дописывай коммиты в ту же ветку и снова пушь её.

## Требования

- CMake 3.20 или новее
- компилятор C++17
- `clang-format` 18 и `clang-tidy` для линтеров

Внешних библиотек нет.

## Сборка

```text
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

## Линтеры

```text
cmake --build build --target format
cmake --build build --target format-check
cmake --build build --target tidy
```

`format` переписывает исходники. `format-check` только проверяет стиль. `tidy` гоняет clang-tidy и проверяет комментарий в теле каждой функции из `algo/order_statistic_algorithm.hpp`.

Первая строка внутри функции — многострочный комментарий. Сначала автор этой функции, затем что она принимает и что возвращает:

```cpp
void example(int value) {
    /*
     * Автор: Имя Фамилия
     * Принимает: value — смысл аргумента.
     * Возвращает: смысл результата.
     */
}
```

У объявления без тела (`= default`, `= delete`, `= 0`) такой строки нет, комментарий там не требуется.

`clang-format` должен быть версии 18, иначе проверка стиля разойдётся с CI:

```text
pip install clang-format==18.1.8
```

## Реализованные алгоритмы

Добавлены три семейства ранее проверенных алгоритмов. Все классы наследуются от
`OrderStatisticAlgorithm<Container>` и используют **нулевые ранги**, как базовый интерфейс.
Конкретные реализации принимают обычный изменяемый `std::vector<T>` со стандартным аллокатором.
Контейнер должен жить дольше объекта алгоритма; его размер нельзя изменять между вызовами.

| Заголовок | Класс | Поведение |
|---|---|---|
| `algo/bfprt.hpp` | `rapid_stats::BfprtAlgorithm` | Медиана медиан, группы по пять, трёхстороннее разбиение |
| `algo/radix_select.hpp` | `rapid_stats::RadixSelectAlgorithm` | Выбор по байтам без полной сортировки |
| `algo/radix_select.hpp` | `rapid_stats::RadixSortAlgorithm` | Дополнительный вариант: полная стабильная поразрядная сортировка |
| `algo/partial_quicksort.hpp` | `rapid_stats::PartialQuicksortAlgorithm` | Сортировка минимального префикса, покрывающего запрошенные ранги |

`sort(ranks)` возвращает итераторы в том же порядке, что и `ranks`. Повторяющиеся ранги
допустимы. Пустой запрос ничего не меняет, в том числе на пустом массиве. Недопустимый
ранг вызывает `std::out_of_range` до перестановок. Неконечные вещественные значения
отклоняются при непустом запросе; нули обоих знаков считаются равными.

```cpp
#include "algo/bfprt.hpp"

std::vector<std::int64_t> data{9, -1, 5, 3, -7, 3, 8};
rapid_stats::BfprtAlgorithm<std::vector<std::int64_t>> algorithm(data);
auto result = algorithm.sort({3, 0, 3});
// *result[0] == 3, *result[1] == -7, *result[2] == 3.
```

Итераторы предназначены для чтения результатов после завершения текущего вызова.
Новый вызов или изменение массива может переставить элементы под ранее полученными итераторами.
У Radix Select итератор указывает на найденное значение, но не обязательно равен `begin()+rank`.
Для равных статистик допустима ссылка на один экземпляр. Чтобы последующие перестановки
внутри одного вызова не испортили результаты, итераторы формируются после всех выборов.

Для Partial Quicksort также доступен `sort_prefix(m)`, где `m` — **количество**, от 0 до n.
`m=0` ничего не меняет; `m=n` полностью сортирует массив. После вызова первые m элементов
совпадают с префиксом отсортированной копии, хвост не содержит значений меньше `data[m-1]`.

BFPRT и Partial Quicksort поддерживают обычные числовые типы, кроме bool.
Поразрядные варианты поддерживают `std::int64_t`, `std::uint64_t` и конечные IEEE 754 binary64
`double`. Ключи учитывают знак; для double биты извлекаются через memcpy, без нарушения алиасности.

### Сложность

- BFPRT: O(n) в худшем случае для одного ранга. Несколько уникальных рангов выбираются
  по возрастанию на оставшемся суффиксе, чтобы не менять ранее установленную статистику.
- Radix Select: максимум восемь байтовых шагов, O(n) для одного ранга при фиксированной
  ширине ключа и O(256) памяти ядра. Адаптер нескольких рангов делает отдельный выбор
  для каждого запроса, затем находит итоговые итераторы: O(qn) времени и O(q+256) памяти.
- Radix Sort: восемь стабильных проходов, O(n+256) времени при фиксированной ширине
  ключа, O(n+256) памяти ядра. Полная сортировка выполняется один раз на запрос.
- Partial Quicksort: ожидаемое O(n+m log m), худшее O(n²), стек O(log n), где
  m=max(ranks)+1. Случайный pivot и трёхстороннее разбиение; seed по умолчанию 20261105.

Оценки памяти не включают обязательный вектор возвращаемых итераторов.
Внутренние ядра находятся в `algo/detail/`; их собственная индексация адаптирована
к публичным нулевым рангам. Вызывайте публичные классы, а не функции из `detail`.

### Проверка реализации

```text
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
cmake --build build --target format-check
cmake --build build --target tidy
```

Тесты сравнивают результаты со std::sort, проверяют несколько рангов, повторы,
повторные вызовы, отрицательные числа, прямой и обратный порядок, все ранги малых
массивов, полный перебор массивов длиной до семи из -1/0/1, ошибки и сохранение
битовых представлений (включая знаки нуля). Для Partial Quicksort проверяются
префикс, хвост, m=0 и m=n. Проверки работают и в Release.

Исполняемые файлы, служебные папки Visual Studio и машинозависимые результаты
локальных замеров не являются зависимостями библиотеки и в исходники не включены.
